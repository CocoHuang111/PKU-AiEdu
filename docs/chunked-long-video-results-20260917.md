# 长视频分块解析：服务器实测结果

测试日期：2026-09-17。服务器：4 核，系统可用总内存约 14.98GiB。

## 结论

此前卡住的视频已成功完成解析并生成完整评估报告，不再反复重启。
分块主要改善长视频处理的内存上限和中断恢复能力，不改变上行带宽。

最终部署 cfe329e 增加缓存身份校验及测试工具，核心分块参数不变。
硬件升级与代码调整同时发生，不能把全部速度差异归因于分块。

## 与旧版的对照

历史原任务在 2 核 8GB 上出现七次主机 OOM 杀进程、八次任务执行记录，未完成。
为确认整段声学计算的风险，在当前服务器上另外运行旧提交 b0b84c9 的声学分析：

- 独立容器，6GiB 内存上限、禁止额外 swap、2 核 CPU，网络关闭，素材卷只读。
- 运行约 69.7 秒后，在整段音频 pYIN 阶段被内存限制杀死。
- Docker 明确记录 `OOMKilled=true`、退出码 137。

这是旧版整段声学计算超过 6GiB 的证据，不是“16GB 服务器必定也会 OOM”的证据。
新版同一完整音频的声学子进程峰值约 465MiB，已经消除了这一整段矩阵内存风险。

## 一致性与恢复测试

选取实际音频 570–630 秒，跨越十分钟位置，做 60 秒回归对照。
为放大切分边界影响，该测试使用 30 秒 ASR 分块；线上默认仍为 600 秒。

| 项目 | 实测 |
| --- | --- |
| 去标点后 ASR 文字一致度 | 89.21% |
| 整段 / 分块音高中位数 | 529.331Hz / 529.3Hz |
| 整段 / 分块音高标准差 | 240.801Hz / 240.8Hz |
| 中断后需要运行的剩余 ASR 子进程 | 1 个，首块未重新识别 |
| 恢复后文字与未中断分块结果 | 完全一致 |

文字一致度是两种识别方式输出的相似度，**不是人工真值准确率**。
分块上下文变化会改变部分文字，不能承诺与整段输出完全一致。
本测试也不能代表两小时全文的准确率；后续应抽样人工检查线上十分钟边界。
音高窗口局部解码也可能在边界产生差异，但该片段的汇总统计接近一致。
没有降低 ASR 模型规格，也没有只分析视频开头或跳过后半段。
