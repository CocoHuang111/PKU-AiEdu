## 为什么需要 Human Effort 框架

AI 使「只交成品」的诱惑骤增。Bowen & Watson 指出：作弊常是**不理解或不重视**作业价值的症状 [1]。 redesign 不仅要「防 AI」，更要让学生理解**为何值得亲自做** — 结合内在动机三要素：

| 动机 | 问句 | 设计回应 |
| --- | --- | --- |
| **I Care（目的）** | 这对我有什么用？ | 明确 skill、职业、课程关联 |
| **I Can（效能）** | 我做得到吗？ | 脚手架、分步、pleasantly frustrated 难度 |
| **I Matter（能动性）** | 我的贡献重要吗？ | 选择、真实受众、可见 impact |

若 AI 能更好更快完成，学生自然会问「为何 me？」— 作业须使**人的声音与判断**可见 [1]。

## Table 10.1：作业说明三要素

每份 assignment sheet 建议包含：

| 块 | 内容 | 示例 |
| --- | --- | --- |
| **Purpose（I Care）** | 为何做、学到什么 | 「本作业训练：从数据论证政策建议，非润色文字」 |
| **Task（I Can）** | What/How/When/Where/With whom | 分步 checklist；是否允许 AI；提交格式 |
| **Criteria（I Matter）** | Rubric、范例、ready-to-submit | 「何谓优于 AI 的论证」见下节 |

与 TILT **Purpose / Task / Criteria** 结构一致 [2]。

## Ready-to-Submit 清单

告诉学生**何时算完成**，也便于用 AI 自检（在 policy 允许时）：

```markdown
## Ready-to-Submit（示例）
- [ ] Thesis 一句可在 30 秒内口头解释
- [ ] 至少 3 个一手/二手来源已核验 DOI/URL
- [ ] 含 AI 使用声明（若 AIAS ≥1）
- [ ] Revision log ≥300 字
- [ ] 格式：PDF，12pt，页码
```

Prompt 给学生（AIAS 2）：「这是我的作业与 ready-to-submit 清单，请逐项检查缺什么，不要替我写作。」

## PROCESS 作业模板（核心）

Bowen & Watson 提供的**通用流程**，适用于多学科 [1]：

### 标准七步

| 步 | 学生活动 |
| --- | --- |
| 1 | 请 AI 生成初稿/代码/方案/实验设计…… |
| 2 | **评价**结果：列错误或可改进处 |
| 3 | **调整 prompt** 改善输出 |
| 4 | 哪版最好？策略是什么？ |
| 5 | 取最佳输出，**人工再编辑** |
| 6 | 向「雇主」说明你的**增值** |
| 7 | 解释为何 human work 优于纯 AI |

### Variation 1：选题与论证链

1. AI 生成 5–10 个 idea → 2. _critique_ 并选一 → 3. 要 outline 变体 → 4. 找遗漏 → 5. 论证为何选此题 → 6. 完成作品 → 7. 反思人指导的关键环节

### Variation 2：Debug / 改进 trade-offs

1. AI 生成/code/create → 2. 找错并修正 → 3. 至少两版「更好」→ 4. 讨论 elegant vs simple 等 trade-off → 5. 改进 prompt → 6. **雇佣理由**：为何雇你而非只用 AI

**教学价值**：better prompts 需**领域 context** — 学生无法完全不思考就抄 AI [1]。

## 与「Better than AI」评分衔接

Ch.8 主张：**AI 产出 ≈ 新 C 档**；rubric 应使 AI-level work **不及格或低分**，B/A 须体现人类增值 [1]。

| Rubric 档 | 含义（简） |
| --- | --- |
| F / AI-Level | 仅达 AI 平均质量 |
| B | 明显修订、论证、情境化 |
| A | 原创洞察、严谨核验、优雅整合 |

详见 `09-AI时代的评价与诚信/Better-than-AI评分与Rubric调整.md`。

## 学科快速映射

| 学科 | PROCESS 焦点 |
| --- | --- |
| 写作 | prompt 迭代 + 论证修订 + 口试 |
| 编程 | AI 代码 + test/debug + complexity trade-off |
| 设计 | AI 草图 + 用户场景修正 + 作品集说明 |
| 社科 | AI 文献综述草稿 + 核验来源 + 本地数据替换 |
| 理科 | AI 实验方案 + 安全/可行性 critique + 实测 |

## Checklist 式学习路径（Problem Set 示例）

Bowen & Watson 给出**带时间盒**的 problem set checklist [1]：快读章节 → 独立做题 → 对照样本 → **用 AI 解一题并比较** → 反思「目标理解而非只完成作业」。

可原样用于数学/统计/经济等：**AI 解一题对比** 环节须在 policy 中允许且计入 formative。

## 边界与风险

- PROCESS 作业增加**批改与阅读 log** 负担 — 可抽样评 revision memo。
- 若 AIAS 0，步骤 1 须改为「教师提供 AI 样本」而非学生调用。
- 「雇用你的理由」在部分文化语境可能显得功利 — 可改为「学术贡献说明」。
