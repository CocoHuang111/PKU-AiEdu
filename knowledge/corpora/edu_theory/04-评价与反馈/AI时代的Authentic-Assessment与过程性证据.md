# AI 时代的 Authentic Assessment 与过程性证据

> 真实任务评价与过程 artifact 在生成式 AI 环境下的设计要点。

**文献性质**：评价理论 + AI 时代 assessment redesign 指南归纳  
**核心出处**：Mueller (2005) Authentic Assessment；TEQSA (2023)；Liu & Bridgeman (2024)  
**整理说明**：authentic 特征据 Mueller；AI 情境策略据 TEQSA 与 Liu & Bridgeman。  
**核实日期**：2026-08-06

## 来源标注说明

Authentic assessment 定义见 Mueller [1]；AI 时代证据策略见 TEQSA [2]、Liu & Bridgeman [3]。

## Authentic Assessment 是什么

Mueller 将 authentic assessment 概括为：**要求学生在真实或仿真情境中，用复杂思维完成真实世界式任务，并按专家标准评价** [1]。

| 传统评价 | Authentic assessment |
| --- | --- |
| 选择题/简答题为主 | 性能、作品、portfolio |
| 脱离情境 | 嵌入专业/生活情境 |
| 单一正确答案 | 多路径、需论证 |
| 产品导向 | **过程 + 产品** |

## AI 时代为何更强调 Authentic + Process

- GenAI 可快速生成「看起来像答案」的文本/代码——**产品 alone 证据效力下降** [2][3]。
- Authentic 不等于「AI-proof」——但可通过**情境化 + 过程证据 + 对话验证**提高可信度。
- 与 `形成性评价与反馈原则.md` 互补：形成性强调 feedback loop；authentic 强调**任务真实性**。

## 六类过程性证据（AI 情境）

| 证据类型 | 说明 | 提交形式 |
| --- | --- | --- |
| **Proposal / outline** | 开题前的思路与结构 | 日期戳文档 |
| **Draft 序列** | 可见修订轨迹 | v1, v2, final + track changes |
| **AI 披露 log** | 工具、prompt 摘要、采纳/拒绝 | 声明表（见 `09-AI时代的评价与诚信/`） |
| **Reflection** | 元认知：学到了什么、AI 局限 | 短反思文 |
| **Peer / instructor feedback** | 他人回应 | 评论截图或纪要 |
| **Oral defense** | 随机追问 | 课堂/录像/预约口试 |

## 任务设计示例

| 学科 | Authentic 任务 | AI 政策配合 |
| --- | --- | --- |
| **写作** | 基于实地采访的特稿 | AI 仅允许 outline；final 须 oral Q&A |
| **编程** | 修复含 bug 的真实开源片段 | AI 允许 explain error；禁止 submit 完整 solution copy |
| **社科** | 用本校公开数据写政策 brief | 数据须本地获取；AI 用于图表草稿 + 人工核验 |
| **医学** | 病例讨论（脱敏） | 禁止上传病例到公共 AI |

## Rubric 设计原则

1. **分开评「过程」与「产品」**——避免只看 polished final。
2. **显式纳入「核验 AI 输出」**——高阶课程可设「找出 AI 错误」项。
3. **避免 competence penalty**——合规披露不应自动降档 [4]。
4. **提供清晰 exemplars**——展示「合格的过程 log」样例。

## 与总结性评价的平衡

- 不必所有作业都 authentic——基础知识仍可用 closed-book quiz。
- 建议：**高 stakes summative** 更依赖 authentic + process；**低 stakes** 用于练习与 formatives。
-  workload 管理：过程证据可**抽样**（如随机 30% 口试）。

## 边界与风险

- Authentic 任务设计成本高——可从一门课一个 unit 试点。
- 口试对语言/焦虑/残障学生有负担——须替代证据 [3]。
- 过程留痕可能滑向 surveillance——明确目的与最小必要。
